# 0012. 実測データと集計モデルを分け、実測データは種別ごとの型で表す

- ステータス: 採用
- 日付: 2026-09-12

## コンテキスト

[ADR 0004](0004-config-driven-generic-records.md) は全種別を1つの汎用レコードで表し、累積DBの列を `config.yaml` から生成する形にした。種別追加が設定1エントリで済む利点は実際に効いており、HRV と呼吸数は設定の追記だけで足せた（PR #16）。

睡眠ステージの取り込みで限界が出た。ステージは「区間の時刻」と「どの日に数えるか（起床日）」が食い違うため、日付を決める時刻をレコードへ持たせる必要がある。ところが汎用レコードにそれを足すと、血圧や体重の保存先にも同じ欄が増える。**ある種別の都合が、無関係な種別の保存先を変えてしまう。**

原因は、汎用レコードが「実測データの表現」と「集計処理の入力」を兼ねていること。集計モデルは集計側の都合で決めたものなのに、それをそのまま保存しているため、集計の都合が保存の形へ漏れる。

## 決定

- 実測データは**種別ごとの型**で表す。累積DBはこれを保存する（テーブルは従来どおり種別ごと）
- **集計モデルは保存しない。** 実測データから変換して作る一時的なものとし、現地日・期間・記録元アプリ・値だけを持つ
- 変換は種別ごとに書く。種別固有の事情（睡眠ステージなら親セッションの終了時刻から起床日を決める）はここに閉じる
- `config.yaml` は廃止する。読み方は種別ごとのコードへ移り、生データの窓や日次関数といった方針も同じ場所に置く。設定は既にイメージへ同梱され環境ごとに差し替えない（[ADR 0002](0002-bundle-config-into-image.md)）ため、変更にビルドが要る点は変わらない
- **やめるのは「種別の型の共通化」であって、定型処理の共有ではない。** 時刻の持ち方の類型ごとのSQL組み立て、重複排除、日次集計、タブ書き込みは共通の部品として残す

## 結果

- 良い影響: ある種別の改修が他種別へ及ばない。種別固有の事情を型で表せる（血圧の収縮期、睡眠ステージの親セッション終了時刻）。値がすべて `float64` という ADR 0004 の制約も種別ごとに外せる。
- 悪い影響: 種別追加が設定1エントリで済まなくなり、`docs/draft/spec.md` の当初要件を捨てることになる。16種別ぶんの読み出しを書く。ADR 0004 を置き換え、ADR 0002 は対象を失う。
- 累積DBの中身は変えないため、移行中は新旧の出力が一致することを突き合わせて確かめられる。

## 検討した代替案

- **保存先の列だけ種別ごとに持たせる**（汎用レコードは残す）: 今回の結合は切れ、変更も小さい。却下: 実測と集計を1つの型が兼ねる構造が残るため、同じ種類の漏れが別の形で再発する。
- **集計モデルの分離だけ行い、実測データの読み出しは設定駆動のまま**: 実装量が小さく、設定1エントリで種別を足せる性質も残る。却下: 種別固有の事情を設定で表す形が残り、表せないものが出るたびに設定の語彙が増える。
- **現状維持（汎用レコードへ欄を足す）**: 最も安い。却下: 無関係な種別の保存先が変わる、という今回の問題がそのまま残る。
