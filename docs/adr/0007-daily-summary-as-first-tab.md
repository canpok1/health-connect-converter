# 0007. Claudeに読ませる正本としてdaily_summaryを先頭タブに固定する

- ステータス: 採用
- 日付: 2026-08-30

## コンテキスト

`docs/draft/spec.md` は出力を Claude の Drive コネクタから読ませる前提だが、実際に読ませると直近データが読めなかった。

原因は3点の噛み合わせ。Drive コネクタにタブ単位・範囲単位で読む手段が無く（Sheets コネクタは未接続）、`read_file_content` は全タブを1文書で返す。全体 918,636 chars は読み取り上限を超える。超過時は各タブの先頭行から詰めて打ち切られ、出力は昇順（`internal/store/store.go` が `ORDER BY ... ASC`）なので **消えるのは常に直近側**になる。`daily_summary` は全1274行のうち164行しか返らなかった。

一方 Drive の `text/csv` エクスポートは先頭タブだけを返す（Google 公式 "Comma Separated Values (first-sheet only)"）。その先頭タブが、手作業でスプレッドシートを作ったときの空の `シート1` のままだった。

## 決定

`daily_summary` を index 0 へ移動し、コードで毎回保証する。`シート1` は削除せず後ろに残す（非破壊であり、index 0 さえ取れれば CSV は `daily_summary` を返す）。CSV エクスポート1回で全期間の日次集計（84,961 chars）が完全に取れるようになる。

あわせて、Claude が見るデータの鮮度は `_meta` ではなく **`daily_summary` の最終行の日付**で判断する。CSV 経路では `_meta` が読めないため。歩数が毎日記録されるので、最終行の日付がパイプラインの生存を示す。

## 結果

- 良い影響: 傾向の振り返りと相関分析が1回の読み取りで完結し、spec の「`daily_summary` 1枚でほぼ完結する」が実際に成立する。
- 悪い影響: これまで無意味だったタブ順に意味が生まれ、並べ替えが破壊的変更になる。壊れると CSV が空や別タブを返すため失敗が静かになる。`_meta` による障害検知は CSV 経路では働かない。生データを見るには xlsx 全体を落としてローカルでパースする別手順が要る。

## 検討した代替案

- **出力を降順（新しい順）にする**: 打ち切られても直近が残る。却下: 切れていること自体に気づけない点は変わらず、人間がシートを見るときに読みにくくなる。
- **Claude 読み取り専用タブを新設し `_meta` と `daily_summary` をまとめる**: 1回の読みで鮮度も取れる。却下: 同じデータが二重に載る。
- **`daily_summary` の先頭数行に `_meta` を埋め込む**: 二重化せずに同じ効果が得られる。却下: テーブルが汚れ、グラフ化や人間の閲覧の邪魔になる。
- **`steps_raw` の窓を縮める**: 全体が軽くなる。却下: それでも `read_file_content` の上限には届かず、spec の用途3「生データを都度自由に分析」も痩せる。
